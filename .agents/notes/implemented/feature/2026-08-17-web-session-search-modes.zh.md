# Agent Note: Web 会话搜索模式

Status: implemented

[English](2026-08-17-web-session-search-modes.md) | 中文

## 问题

字面短语搜索无法用 `spatiotempora` 这类未输入完整的最后一个 token 命中 `spatiotemporal`，侧边栏也没有区分大小写、全字或正则表达式查询的控件。把每次按键都发送到全局索引，还会让一两个字符的输入产生不必要的高成本搜索。

## 决策

默认 SQLite 查询仍是不可执行的字面短语，但会在短语后添加 FTS5 前缀标记，只扩展最后一个 token。`matchWholeWord` 会移除该扩展。`matchCase` 保留索引候选项查询，并使用索引中的原始文档文本复核匹配。`useRegularExpression` 保留查询内部空白，并用 Unicode JavaScript 正则表达式扫描索引中的原始文档文本；`matchCase` 控制大小写折叠，`matchWholeWord` 添加 Unicode 单词边界。无效表达式会在查询执行前失败。

Web `session.search` 请求通过 runtime 和 Host 网关传递三个可选控制项。侧边栏在展开的搜索框内用 `Aa`、`ab` 和 `.*` 开关呈现这些控制，并把相同控制应用于即时标题与 Workspace 匹配。少于三个 Unicode 字符的查询只在本地执行。更长的有效查询会在最后一次输入或选项变更后等待 350 ms 再开始，替代查询会中止前一个请求。无效正则表达式显示本地错误，绝不会到达 Host。

## 考虑过的替代方案

- **只在浏览器中过滤 Host 返回的第一页**：不采用，因为位于前 20 个提供方命中之外的匹配 Session 会消失，使这些控制项不完整。
- **把 FTS5 查询语法作为正则表达式模式**：不采用，因为 FTS5 运算符不是正则表达式，而且会暴露提供方语法，而不是实现界面声明的行为。
- **每输入一个字符都执行搜索**：不采用，因为标题匹配已经提供即时反馈，而一两个字符的全局内容扫描选择性很低。

## 后果

最后一个 token 的部分查询和三个显式匹配模式可跨可见的实时与持久化 Session 工作，同时保留 Host 授权和精确结果导航。默认字面搜索与区分大小写搜索保留 FTS5 候选项路径。正则表达式更灵活，但会同步扫描索引中的原始文档，其阻塞时间可能长于索引搜索；三个字符的 UI 门槛与 350 ms 防抖会减少意外扫描，而不改变直接服务调用方。

## 验证

SQLite 测试固定前缀、区分大小写、全字、正则表达式和无效模式行为。runtime 与 Host 测试固定协议转发。Workspace 测试固定延迟、短查询抑制、选项控件、本地匹配、无效模式处理、取消与结果导航。
