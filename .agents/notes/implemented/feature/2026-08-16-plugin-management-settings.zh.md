# Agent Note: Web 设置管理 profile 包与运行时插件

Status: implemented

[English](2026-08-16-plugin-management-settings.md) | 中文

## 问题

DSH profile 可以组合 registry 包、GitHub 依赖、本地 link、安装自有插件和 Cordis builtin，但 Web 设置此前只提供 Loader 条目的只读投影。用户无法判断哪个直接依赖拥有某个已安装产物、外部插件来自哪里，或某一行究竟属于 DSH 原生、内置、外部还是本地。更新包仍需通过 `dsh plugin` 向 pnpm 转发参数；尽管 Loader 已支持实时更新，启用或停用 Loader 条目仍要手工编辑 patch 文件。

把每个 Loader 行都当作独立安装包并不正确。一个直接聚合依赖可以引入多个运行时模块，因此更新叶子模块名称可能绕过真正拥有 profile 安装关系的包。包替换还会改变磁盘文件，无法让已经 import 的 JavaScript 安全采用新产物；而 Loader 启停属于进程内生命周期转换，可以立即生效。

## 决策

插件管理 Remote 与设置标签页显式提供两份清单。**已安装包**只来自 profile 的直接 `dependencies`；每项报告请求 spec、已安装版本、registry／GitHub／本地来源、组合包成员关系、包元数据声明的 GitHub 仓库，以及适用时解析出的本地路径。只有这些包身份可以更新。**运行时插件**来自 `ctx.loader.entries()` 中的非 group 条目，报告确切的 Loader 身份、模块／包信息、DSH 原生／Cordis 内置／外部／本地来源、生效的启用状态、生命周期阶段与切换资格。

一键更新刻意只是更新操作，而不是通用包管理器。每个远程包保留自己的操作，同时提供一个分组操作，依次对每个支持更新的直接依赖执行同一流程，在单包失败后继续，保留逐包结果，并汇总已更新／已是最新／失败数量。registry 依赖运行 `pnpm outdated`，仅在存在新版本时升级到最新发行版；GitHub 与其他远程 spec 刷新其已配置来源；`link:`、`file:` 与 `workspace:` 依赖保持只读，并把用户指向其源码 checkout。命令经由受管 subprocess 服务执行，不经过 shell，同时实施串行修改、有界输出、超时和包名成员校验。包文件发生变化时会设置 `restartRequired`，因为当前 DSH Web 进程已经 import 其插件图。

运行时启停通过 `ctx.loader.update()` 立即完成热插拔转换，并把期望布尔值持久化到当前 profile manifest 的 `dsh.profile.entryStates[entryId]`。启动时会把该映射投影成 Loader patch，位于 profile 与 home 用户 patch 层之后、显式命令行 overlay 之前，因此 UI 状态可以跨重启生效，同时不会夺走操作者启动 overlay 的最终权威。持久化失败时会回滚实时转换。结构性的树承载条目和管理控制平面不能从该界面切换，从而避免页面断开自己的 Remote、服务器、Client runtime 或设置依赖。

## 考虑过的替代方案

- **把每个 Loader 条目建模为已安装包**：不予采纳。聚合组合包可以拥有多个叶子模块，包 specifier 不必等于 Loader 模块名，更新叶子会修改错误的依赖边界。
- **每次切换都改写 `cordis.patch.yml`**：不予采纳。这些文件保存用户编写的完整配置 patch，并采用整体替换 config 的语义。专用布尔映射无需改写或解释用户 YAML，同时仍复用同一组合算法。
- **把包更新作为运行时热重载应用**：不予采纳。pnpm 可以替换任意依赖图与已导入模块状态，进程重启才是采用已变更包产物的真实边界。
- **允许每一行停用自身**：不予采纳。停用 Loader 子树或管理控制平面可能移除从浏览器恢复它所需的机制本身。

## 后果

- Web 设置现在会分开列出直接安装包与运行时插件，显示来源标识、GitHub 链接或本地路径，并在正确的所有权边界提供包更新与运行时启停控件。
- 外部包既可单独更新，也可通过一个分组操作统一更新。分组操作会串行执行、跳过本地依赖、在某个包失败后继续、展示逐包结果并汇总整次运行；更新结果会提示用户重启 DSH Web。本地插件仍由其源码负责，必须在 checkout 中重新构建。
- 运行时切换立即生效并跨重启保留。已启用子条目位于停用父级下时，仍可能处于实际停用状态；Remote 返回生效状态，UI 会说明期望子状态已经保存。
- 清单仍只表示调用当下，不订阅其他位置产生的变化。标签页会在自身更新后刷新，并局部应用自身的切换结果；重新打开或重试后才会取得其他变化。
- 包安装／移除、本地仓库拉取／构建和持久故障历史仍不属于该管理界面的范围。
