## Design Context

### Users

DeepSeek Harness Web is used by developers and local operators who configure, inspect, and run a plugin-based agent harness. They need to understand the active composition quickly, change it without leaving the browser, and see whether an operation affected configuration, the live Cordis runtime, or an installed package.

### Brand Personality

Calm, technical, and exact. The interface should build confidence through explicit state, restrained styling, concise Chinese copy, and clear recovery paths rather than decorative presentation.

### Aesthetic Direction

Use the existing light and dark token system and compact settings layout. Favor dense, scan-friendly rows, progressive disclosure, familiar controls, and small semantic status accents. Preserve the current DeepSeek Web visual language; avoid marketing composition, ornamental cards, oversized type, gradients, and novelty motion.

### Design Principles

1. Show the authoritative source of every state and distinguish installed packages, local links, and built-in plugins.
2. Keep risky or unavailable actions visibly constrained and explain why they cannot run.
3. Make configuration changes reversible and report live-runtime and package-operation outcomes separately.
4. Keep common plugin management actions in one details surface without hiding diagnostics.
5. Preserve keyboard access, responsive layout, reduced-motion behavior, and semantic status cues beyond color.
